# Test catalogue

The acceptance suite for hearth-engine, a Swift + Metal 2D renderer, and for its first consumer, IdleVillage
(a cozy isometric idle game whose art comes from a Blender-based "village kit"). Written before the engine, so the
engine is built against it. Draft of 2026-11-25. Every test names the need it serves: an asset contract, a game
requirement, or a failure another engine had (`research/engine-pitfalls.md`).

Decisions this catalogue depends on are in `Decisions.md` (D1 compositing space, D6 asset format, ...). Tests that
pin an open decision say so.

## Suites

| Prefix | Suite | Where | Runs |
|---|---|---|---|
| **E** | Engine | this repo, `swift test` | every commit on an Apple-silicon Mac; GPU tests skip when no Metal device exists (hosted CI) and run on a self-hosted Mac. A skipped test never counts as passed (E-PROOF-2). The Simulator smoke tests (E-SIM) run through `xcodebuild` on the iOS Simulator |
| **D** | Device | this repo, benchmark app, XCTest `measure` | per engine release, on the test devices (D2) |
| **B** | Build | this repo and the game's CI | every commit |
| **K** | Kit | IdleVillage, `scripts/village_kit` (art track) | `make asset-selftest` / `make asset-test` |
| **C** | Consumer | IdleVillage, unit tests (`scripts/agent-test.sh`) | every commit once `Game/` is unparked |
| **U** | Consumer UI | IdleVillage, UITests and player journeys | every commit once `Game/` is unparked |

Kinds: **P** pure (no GPU), **G** golden image (offscreen render compared to a reference), **M** measured on
device, **S** static check (lint, plist, manifest), **R** frame report (assertions on the JSON frame report of
D22; its *intended* half needs no GPU, its *observed* half does). A report-based pass never stands in for a test
whose kind is G or M.

## Golden-image method

- Render offscreen into a fixed-size texture with fixed time, seeds and format; blit to a shared buffer; compare.
- **Dither frozen** in golden mode (off, or a seeded static pattern); dither has its own tests (E-QUAL-7, -8).
- **References:** kit references first (the kit renders the expected result: `sprite.png`, per-frame
  `layercheck/` renders, Blender oracle scenes), so the engine is judged against Blender, not against itself.
  Engine references (grade, particles, fog) are reviewed by eye, committed with a reason, and kept **per GPU
  family** (Apple does not guarantee numerical consistency across devices).
- **Two tiers:** analytic and same-config tests: per-channel |Δ| ≤ 2/255 on ≥ 99.9% of pixels and ≤ 8/255 on all
  (exact where the test is analytic). Art-level and cross-config tests: NVIDIA FLIP mean and a 99th-percentile cap.
  Save the FLIP map as an artifact on failure.
- **Calibration:** run each scene 20 times on one device; set thresholds at about 3x the observed noise.
- Small feature-isolated scenes (one subsystem each) plus one full "postcard" scene as a smoke test.
- The kit's own layers-gate tolerance (24 levels on ≤ 0.5% of covered pixels) is the ceiling for composite tests,
  not the target.
- **Reference path (D18):** references are recorded only from the single-pass path on a real Apple GPU (the Mac
  harness or a device). The two-pass fallback is tested against that path (E-PASS-4); the iOS Simulator never
  produces a reference (E-SIM-2).
- **Proof rules (D22):** a reference changes only with a human approval record (E-PROOF-1); every run writes a
  receipt and a skipped test is not a pass (E-PROOF-2); every golden test has a negative control that must fail
  (E-PROOF-3); scenes carry their intent as checkable statements (E-PROOF-4).

## Conformance corpus

Two tiers (D21). The engine never reads a kit manifest (E-CORPUS-2).

**Synthetic tier.** Owned by this repo and generated by code, deterministically (E-CORPUS-1); no binary assets
are committed for it. Flat colours, alpha and colour ramps, numbered tiles, saturated neighbours, sheets with
numbered cells, boxes of known footprint and height, on three projections: a (48, 28)-pt diamond, a 2:1 diamond
and an orthogonal grid. It serves every analytic test and every grid feature (E-GRID, E-ELEV, E-SORT, E-LAYER,
E-PICK, E-RPT).

**Art tier.** Exported by the kit (`make asset-corpus`, K-CORPUS-1), versioned by `KIT_VERSION`, vendored here
pinned, in engine formats: texture containers, Blender references, and scene files exported by the consumer's
adapter (C-EXPORT-1). Used in this repo only where Blender must be the judge (E-COL-5, E-QUAL-1, -2, -4), and by
the consumer suite for everything else. One asset per feature so a failure names the feature:

| Entry | Exercises |
|---|---|
| windmill | `spin` part, shadowless part |
| sawmill | `frames` part (8-cell sheet), review-only smoke, glow |
| woodlot | three `sway` parts with phases, back-to-front parts |
| bakery | additive glow, smoke review layer |
| farmyard | crop canvas, base + glow only |
| grass + plots/* | tile canvas, diamond, 3x3 repeat, four overlays |
| chicken | critter sheets, five rows, mirrored right-facing rows, three animations |
| goods_wood/logs, goods/bread | icon canvas at 24, 32, 48 pt |
| silo t1, t2 | tier variants |
| oracle scenes | Blender renders of small composed layouts at device pixel size (E-COL-5, E-QUAL-1) |

### E-HAR: harness and determinism

| Id | Requirement | Kind | Pass |
|---|---|---|---|
| E-HAR-1 | Render headless into an offscreen texture of any size; no view, no display link | G | A 1x1 red quad reads back exactly where placed |

### E-GOLD: golden comparison (*Golden-image method*)

The comparison itself is code, so it has tests: a comparison that cannot fail proves nothing (E-PROOF-3).

| Id | Requirement | Kind | Pass |
|---|---|---|---|
| E-GOLD-1 | The near-exact tier applies the method's rule | P | Per-channel differences of at most 2/255 on at least 99.9% of pixels and at most 8/255 on all pass; one pixel at 9/255, or more than 0.1% of pixels over 2/255, fails; the exact tolerance passes only equal images; images of different sizes are a typed error |
| E-GOLD-2 | The FLIP tier scores as the paper defines and gates on the mean and on the 99th percentile | P | Identical images score 0 everywhere; pure green against pure blue scores 1; a comparison fails when the mean is over its limit and fails when the 99th percentile is over its cap, each on its own |
| E-GOLD-3 | A failed comparison leaves its evidence | P | A failure writes the actual image, the expected image and the difference map (the FLIP map on the FLIP tier) as PNG files that decode to those pixels; a pass writes nothing |
